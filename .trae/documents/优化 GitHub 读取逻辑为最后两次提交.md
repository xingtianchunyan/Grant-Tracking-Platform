# 优化 GitHub 提交信息读取逻辑

根据您的要求，我们将把 GitHub 仓库信息的读取量从“读取所有”或“固定读取10条”修改为**仅读取最后两次提交**。这样可以显著减少数据处理量，同时仍能满足“检测是否有新活动”的需求。

## 实施计划

### 修改 `app/api/cron/risk-scan/route.ts`

1.  **修改 Commits 获取逻辑**：
    *   将 `per_page=10` 改为 `per_page=2`。
    *   这不仅会减少 API 返回的数据量，还会让循环处理更快。

2.  **修改 PRs 获取逻辑**：
    *   同样将 Pull Requests 的获取数量从 `per_page=10` 减少到 `per_page=2`。

3.  **验证**：
    *   手动运行风险扫描脚本，确保修改后的逻辑依然能正常工作（即 `repo_check` 依然为 `checked`）。

这将是一个非常直接且低风险的修改。
